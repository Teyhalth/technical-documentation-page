Git & GitHub for Beginner

Welcome to the Git & GitHub Guide For Beginner! This documentation is designed for beginners who are learning how to use Git and GitHub for the first time.

Git can seem confusing at first, but once you understand the basic commands and how Git works, it becomes an essential tool for managing your projects.

A simple way to remember the difference is:

  • Git = the tool that tracks your changes.
  • GitHub = an online platform where you can store and share your Git repositories.
What is Git?

Git is a distributed version control system created to help developers manage changes to their code.

Git allows you to keep track of changes within the same project.

Git can help you:

  • track changes to files
  • Work with other developers
  • Keep a history of your project
Basic Git Commands

Here are some of the most commonly used Git commands:

git init

Creates a new Git repository.

git init

git status

Shows the current state of your repository.

git status

git add

Adds changes to the staging area.

git add index.html

You can also add multiple files:

git add .

git commit

Saves the staged changes to your Git history.

git commit -m "Add homepage"l

The message inside the quotation marks should briefly describe what you changed.

Staging and Committing

Git uses a staging area before changes are committed.

A simple way to understand the process is:

Working Directory
↓
git add
↓
Staging Area
↓
git commit
↓
Git Repository

For example:

git status
git add .
git commit -m "Update website"
  1. The first command checks your changes.
  2. The second command stages the changes.
  3. The third command records the changes in your Git history.
Connecting to GitHub

After creating a repository locally, you can connect it to a GitHub repository.

First, create a repository on GitHub.

Then connect your local repository to the remote repository:

git remote add origin https://github.com/username/repository-name.git

You can check the remote repository with:

git remote -v

The word origin is commonly used as the name of the remote repository.

Push and Pull

Push

The git push command sends your local commits to a remote repository such as GitHub.

For example:

git push -u origin main

After the first push, you can usually use:

git push

A simple way to remember it:
Push = send your local changes to GitHub.

Pull

The git pull command downloads changes from a remote repository and updates your local project

git pull

A simple way to remember it:
Pull = get changes from the remote repository.

Branches

Branches allow you to work on different versions of a project without directly changing the main branch.

To create a new branch:

git branch feature

To switch to the branch:

git switch feature

You can also create and switch to a branch using:

git switch -c feature

Branches are useful when developing new features or testing changes.

.gitignore

A .gitignore file tells Git which files or folders should not be tracked.

For example:

node_modules/
.env
*.log

You might use .gitignore for:

  • Secret files
  • Passwords or API keys
  • Large generated files
  • Operating system files

Example .gitignore

node_modules/
.env
.DS_Store
*.log

Never commit passwords, private keys, or other sensitive information to a public repository.

Common Git Problems

Not a Git Repository

If you see:

fatal: not a git repository

Make sure you are inside your project folder and run:

git init

Nothing to Commit

If Git says:

nothing to commit, working tree clean

It means there are no new changes to save.

Check your files with:

git status

Accidentally Added Files

If you accidentally use:

git add .

You can unstage the files with:

git restore --staged .
